# Synthetic fixtures

Authority: the implementation plan, Section 8 (Phase 0: "Add a deterministic
synthetic fixture generator; do not hand-copy real sessions"; exit gate:
"Generated fixtures reproduce byte-for-byte from a recorded seed") and
Section 10 ("Adapter tests": normal, large, malformed, partially written,
and rewritten synthetic sessions). The generator is
[`tools/fixturegen.py`](../../tools/fixturegen.py); the corpus is committed
under [`fixtures/synthetic/`](../../fixtures/synthetic/).

No fixture byte is copied from any real harness store. Every record is
assembled from a closed vocabulary, fixed identifier shapes, and a seeded
bit generator, which is what makes "contains no private transcript,
credential, path, hostname, or account identifier" a machine-checkable
property rather than an assertion.

## Layout

```text
fixtures/synthetic/
├── sessions/          normal complete sessions, plus two named specials:
│   ├── additive-fields.jsonl   assistant records carry optional extra
│   │                           fields (old-reader forward compatibility)
│   └── truncated-life.jsonl    valid records only; the session never ended
├── rewritten/         per session: gen-0001..gen-0003 snapshots. Each later
│                      generation keeps a byte-identical line prefix of the
│                      previous one, then records a compaction and fresh
│                      records — a rewrite, not an append
├── large/
│   ├── marathon/      one month-scale session (1200 records)
│   └── history/       six synthetic accounts, twelve sessions each
├── malformed/         one file per defect, tagged in the manifest
└── manifest.json      schema, seed, shape parameters, per-file digests
```

Malformed defects, one per file: `empty`, `blank-lines`,
`invalid-json-line`, `non-object-line`, `missing-type`, `wrong-type-id`,
`duplicate-ids`, `nul-byte`, `invalid-utf8`, `truncated-tail`. The
`nul-byte` and `invalid-utf8` files splice raw bytes between whole
vocabulary words or inside a multibyte character, so they remain defective
without introducing foreign text. `truncated-tail` removes exactly the
final closing quote, brace, and newline — a partially written final record
whose last word is still complete.

## Determinism

- The only entropy source is a SHA-256 counter-mode DRBG keyed by the seed
  string recorded in `manifest.json`. No clock, environment, locale,
  hostname, filesystem ordering, or `random` module is consulted;
  newlines are always `\n`; timestamps are rendered by integer arithmetic
  (Hinnant's civil-from-days) over a fixed window starting 2026-01-05.
- The JSON writer is hand-rolled: fixed call-order field order, `", "`
  separators, integers only (no floats), and raw UTF-8 for non-ASCII text,
  so byte output does not depend on a serializer version.
- `--verify` regenerates the corpus from the manifest seed with the current
  code and byte-compares every file against the working tree. It also
  checks schema/parameter agreement, the per-file digests, the aggregate
  `corpus_digest`, and that the working tree contains exactly the manifest
  file set. Any drift — hand-edited corpus, regenerated-without-committing,
  vocabulary or shape change, or a file dropped into the tree — fails the
  gate.
- Changing the vocabulary, record shapes, or corpus counts changes the
  regenerated bytes. The workflow is: edit the tool, run
  `python3 tools/fixturegen.py --generate fixtures/synthetic`, and commit
  the tool, corpus, and manifest together. Bumping `SCHEMA`
  (`archivist.synthetic-fixtures/v1`) marks a corpus-format version event.

A different seed yields a different corpus (different digests); the
canonical seed is a constant recorded in both the tool and the manifest.

## Content safety

Constructive constraints — the corpus cannot contain private material
because the shapes that carry it are never emitted:

- record text uses only the fixed noun/adjective/verb/function-word
  vocabulary (nature words, deliberately free of technology or
  infrastructure terms);
- identifiers are UUIDv4-shaped hex, `acct-` plus eight hex digits,
  `proj-word-word`, `synthetic-word-NNN`, or integer timestamps — never
  real account names, handles, or emails;
- the serializer emits no `/` or `@` byte anywhere in the corpus, so no
  absolute path, URL, email, or handle can appear.

The `--verify` content scan then proves it, with four rules over every
corpus file:

1. **Markers** — raw `/` and `@` bytes, an infrastructure denylist (the
   private hostnames and account markers this project must never republish),
   and credential-shape patterns (key prefixes, private-key blocks,
   keyword assignments) must be absent.
2. **Closed vocabulary** — every ASCII letter run (underscore-joined tokens
   part by part) must be a vocabulary, structural, or enum token, modulo
   case for sentence capitalization; pure `a-f` runs are permitted as
   artifacts of the synthetic hex identifiers.
3. **Keys** — every JSON key on a parseable line must be in the recorded
   key set.
4. **Values** — every string value on a parseable line must match one of
   the synthetic shapes (UUIDv4, timestamp, account, project, model, tool
   name, enum value, or vocabulary sentence).

Findings are content-free: they name the rule, file, and line, never the
matched bytes — the same redaction ethos as the `gitleaks --redact` lanes.
The manifest itself is structural metadata (paths, digests, parameters) and
is validated by digest rather than by the vocabulary scan.

## Verification wiring

`scripts/definition-of-done.sh` runs `python3 tools/fixturegen.py --verify`
in the fast lane: it is offline, content-free in its output, and completes
in well under a second at the current corpus size (99 files, ~455 KiB).
The manifest's `corpus_digest` is the value downstream verification
manifests can record as the fixture digest for a given commit.
