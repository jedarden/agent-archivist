# Authentic Pi JSONL v1/v2 corpus

This directory is a small, read-only corpus of session JSONL emitted by the
official Pi coding-agent package. It exists to give the Pi adapter durable
positive artifacts for both supported historical header versions without
checking in a real user's transcript.

The files are preserved byte-for-byte as emitted by the package runs. The
checksums and source records are in [`manifest.json`](manifest.json).

## Contents

| Artifact | Adapter fingerprint | Header form |
| --- | --- | --- |
| `session-v1.jsonl` | `pi-jsonl-v1` | Legacy v1: the `version` member is omitted; Pi treats it as version 1. |
| `session-v2.jsonl` | `pi-jsonl-v2` | Explicit `"version": 2`; entries carry `id`/`parentId` tree links. |

Each file has exactly two JSONL records. The first is the session header. The
second is an empty assistant message retained only because the corresponding
Pi writer flushes a newly-created session when an assistant message is saved.
It has no prompt, model response, tool call, tool result, extension payload, or
provider credential.

## Provenance and review

Both artifacts were generated on 2026-09-28 in an isolated working directory
by importing the real `SessionManager` from the public npm package named in the
manifest. The v1 run used `@mariozechner/pi-coding-agent` 0.30.0 at upstream
tag `v0.30.0`; the v2 run used 0.32.0 at `v0.32.0`. The package tarball
integrities, upstream commit IDs, writer calls, byte lengths, and SHA-256
values are recorded in the manifest.

The review covered every byte of both files. It confirmed:

- both files parse as JSONL and their first objects are valid Pi session
  headers for the claimed versions;
- no credential-looking field or value is present (there are no credentials,
  tokens, API keys, authorization headers, provider names, or tool payloads);
- `/workspace/pi-jsonl-corpus` is a neutral generation path, not a host path;
- session IDs, entry IDs, and timestamps were generated by the isolated writer
  run and are not copied from a user or host session; they are retained only
  because Pi requires them for a valid artifact;
- no user name, home directory, hostname, repository path, prompt, transcript,
  or unnecessary sensitive content is present.

Consumers must treat this directory and its manifest as read-only corpus data.
The Pi adapter opens source files read-only; any derived test output belongs in
a temporary directory and must not be written here.

The deterministic check is:

```text
python3 tools/check-pi-jsonl-corpus.py
cargo test -p archivist-adapter-pi --test pi_corpus
```

The first command validates manifest discovery, provenance, checksums, both
header versions, and the sanitization review. The focused adapter test then
discovers both files from this directory, captures their complete JSONL
records, and confirms the source bytes are unchanged. Both commands consume
the corpus read-only; their exact command strings are also pinned in
`manifest.json`.
